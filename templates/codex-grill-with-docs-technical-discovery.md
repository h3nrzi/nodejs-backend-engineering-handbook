# Codex starter — Module Technical Discovery (Module-Driven Workflow V2)

Read the owner-approved `final-prd.md`, `module-plan.md`, and the brief for **one selected module**. Inspect installed Matt Pocock skills and existing applicable ADRs. Run `grill-with-docs` in Tech Lead role **only for current module's implementation-blocking engineering decisions**.

Review existing cross-cutting decisions first. Separate adopted, unverified, and legacy/context-only decisions; never silently reactivate a past project plan. Record alternatives, meaningful trade-offs, owner approval, testable evidence gaps and qualifying ADRs. Escalate product-contract changes to the owner; do not rewrite the Final PRD during technical grilling.

Stop interviewing when the module has enough approved architecture to create a complete `to-spec` plan. Defer other modules' engineering to their own sessions. Then `to-spec` → `to-tickets` → `implement` → verify module acceptance. Use the actual installed skill command names. Do not initiate an unbounded whole-product technical decision tree.
