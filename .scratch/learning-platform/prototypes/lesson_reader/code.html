کار با جریان‌ها (Streams) و کنترل فشار بازگشتی

schedule زمان تخمینی: ۲۵ دقیقه مطالعه دقیق assignment_turned_in پروژه عملی الزامی

یکی از مهم‌ترین نقاط قوت پلتفرم Node.js، امکان پردازش داده‌ها به صورت پیوسته و گام‌به‌گام از طریق Streams است. هنگامی که سرور ناچار است یک فایل چندصد مگابایتی یا داده‌های ترافیک سنگین شبکه را به یک کلاینت منتقل سازد، تخصیص حافظه رم برای بارگذاری کامل فایل از طریق متدهای همگام یا حتی fs.readFile، موجب سرریز شدن بافر و افت محسوس پاسخ‌دهی پردازنده خواهد شد.

account_tree جریان داده از منبع به مقصد همراه با مدیریت بافر Buffer Cap: 64KB chunks

در زمان مسدود شدن کلاینت یا کندی شبکه، رویداد drain فراخوانی شده و خواندن از دیسک موقتاً متوقف می‌گردد.

تکنیک فشار بازگشتی (Backpressure) هنگامی نمایان می‌شود که سرعت فرستنده از سرعت توان پردازش گیرنده بیشتر باشد. متد پیش‌ساخته pipe() به طور خودکار ارسال داده را در صورت پر شدن بافر موقت مقصد متوقف ساخته و پس از تخلیه بافر به وسیله رویداد تخلیه (Drain) انتقال داده را از سر می‌گیرد.

اصل اساسی بازدهی حافظه

استفاده از جریان‌ها ردپای حافظه سرور شما را در فایل‌های بسیار حجیم (حتی گیگابایتی) به اندازه چند مگابایت بافر ثابت نگه می‌دارد. این رویکرد زیرساخت شما را در برابر حملات محروم‌سازی سرویس (DoS) مبتنی بر پر شدن حافظه مقاوم می‌کند.

server-streaming.js 
const http = require('http');
const fs = require('fs');

const server = http.createServer((req, res) => {
  const stream = fs.createReadStream(__dirname + '/data.txt');
  stream.pipe(res);
});

server.listen(3000);
